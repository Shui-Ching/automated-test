# [PAG-ADM-FN-002] 後台 新增頁面

## 1. 商業邏輯

| 項目 | 定義 |
| :--- | :--- |
| **需求描述** | 身為 後台管理人員，我想要 新增一筆含多組圖文版型與內容的頁面資料，以便於 在前台呈現對應的頁面內容。 |
| **使用對象** | 後台管理人員 |
| **前提條件** | 使用者具備後台登入狀態。 |
| **基本流程** | 1. 使用者於 `[PAG-ADM-FN-001] 後台 頁面列表` 點擊「新增」進入本畫面，畫面預設顯示 1 組空白圖文區塊。<br>2. 使用者輸入頁面名稱、選擇建立日期。<br>3. 使用者於第 1 組圖文區塊選擇版型，並上傳區塊圖片、輸入圖說文字。<br>4. 使用者點擊「新增圖文區塊」，系統於現有區塊下方追加一組空白圖文區塊，重複步驟 3。<br>5. 使用者點擊任一組之「移除」，系統移除該組並將其後各組依序上移。<br>6. 使用者於頁面內容編輯器輸入圖文內容。<br>7. 使用者輸入補充說明。<br>8. 使用者點擊「儲存」。<br>9. 系統驗證欄位規則後寫入資料，反饋成功訊息並導回 `[PAG-ADM-FN-001] 後台 頁面列表`。 |
| **異常流程** | 無 |
| **特殊規則** | 1. 圖文區塊為可重複群組，數量下限 1 組、上限 3 組。<br>2. 圖文區塊之呈現順序即畫面由上而下之排列順序，與 `[PUB-WEB-FN-002] 前台 頁面內容顯示` 之呈現順序一致；本版不提供拖曳調整順序。<br>3. 建立日期為業務日期，由使用者指定，非系統寫入時間。<br>4. 系統於本功能寫入資料時另存不對使用者顯示之「建檔時序」，其後不因編輯而變更，作為建立日期相同時之次要排序依據；使用處見 `[PAG-ADM-FN-001] 後台 頁面列表` 與 `[PUB-WEB-FN-001] 前台 前台頁面列表` 之〈預設排序定義〉。<br>5. 本頁之後台共用框架依 `[PAG-ADM-FN-001] 後台 頁面列表`〈按鈕與動作〉。<br>6. 本頁之存取權限阻斷依 `NFR-001`；登入逾時處理依 `NFR-002`；資料寫入失敗處理依 `NFR-004`。 |
| **參考資料** | 無 |

### 按鈕與動作
*   **新增圖文區塊**：於現有圖文區塊下方追加一組空白區塊。已達 3 組時本按鈕停用（採輸入即擋，不觸發錯誤提示）。
*   **移除（各組圖文區塊）**：移除該組區塊及其已填內容，其後各組依序上移。僅剩 1 組時本按鈕不顯示。
*   **儲存**：完成檢核後寫入資料，Toast 提示文案為「新增成功」，顯示後導回 `[PAG-ADM-FN-001] 後台 頁面列表`。
*   **返回**：不儲存放棄本次輸入，導向回 `[PAG-ADM-FN-001] 後台 頁面列表`。
*   **通用行為**：儲存處理期間按鈕停用，防重複送出。

## 3. 驗收條件

### 正常情境（預期成功）

*   **AC-P1：以單組圖文區塊成功新增頁面**
    *   **Given**: 使用者位於新增頁面畫面，且系統中不存在頁面名稱「品牌故事」。
    *   **When**: 使用者輸入頁面名稱「品牌故事」、建立日期「2026-03-01」，於預設之第 1 組圖文區塊選擇「左圖右文」、上傳一張 JPG 圖片並輸入圖說文字後點擊「儲存」。
    *   **Then**: 系統應寫入該筆資料、顯示成功提示（文案見〈按鈕與動作〉）並導向至 `[PAG-ADM-FN-001] 後台 頁面列表`，其中可見「品牌故事」，該筆之「圖文區塊」欄顯示為「1 組」。
*   **AC-P2：以三組圖文區塊成功新增頁面**
    *   **Given**: 使用者位於新增頁面畫面，已填妥頁面名稱與建立日期。
    *   **When**: 使用者點擊「新增圖文區塊」兩次使畫面呈現 3 組區塊，依序將版型設為「左圖右文」、「右圖左文」、「左圖右文」並各自上傳圖片後點擊「儲存」。
    *   **Then**: 系統應完整保存三組區塊及其各自之版型、圖片與圖說文字，`[PAG-ADM-FN-001] 後台 頁面列表` 該筆之「圖文區塊」欄顯示為「3 組」。
*   **AC-P3：移除圖文區塊後其後各組上移**
    *   **Given**: 使用者位於新增頁面畫面，畫面已呈現 3 組圖文區塊，圖說文字依序為「甲」、「乙」、「丙」。
    *   **When**: 使用者點擊第 2 組之「移除」。
    *   **Then**: 畫面應僅剩 2 組區塊，其圖說文字依序為「甲」、「丙」，且「新增圖文區塊」按鈕由停用恢復為可點擊。
*   **AC-P4：頁面內容以 HTML 格式保存**
    *   **Given**: 使用者位於新增頁面畫面。
    *   **When**: 使用者於頁面內容編輯器輸入一段含粗體與項目清單之內容，並完成儲存。
    *   **Then**: 系統應以 HTML 格式保存該內容，再次於 `[PAG-ADM-FN-003] 後台 編輯頁面` 開啟該筆時，編輯器內之粗體與項目清單格式應完整還原。
*   **AC-P5：同日新增之次要排序**
    *   **Given**: 系統中不存在建立日期為 2026-04-01 之頁面資料。
    *   **When**: 使用者以建立日期「2026-04-01」先後新增「甲頁面」與「乙頁面」。
    *   **Then**: `[PAG-ADM-FN-001] 後台 頁面列表` 中「乙頁面」應排序於「甲頁面」之前。

### 阻擋情境（預期擋下）

*   **AC-B1：欄位驗證（概括）**
    *   **Given**: 使用者位於新增頁面畫面。
    *   **When**: 任一欄位（含任一組圖文區塊內之欄位）不符〈欄位驗證〉表所定義之規則，使用者點擊「儲存」。
    *   **Then**: 系統應阻擋儲存，並於對應欄位觸發該規則之錯誤提示（規則與文案見〈欄位驗證〉表，此處不重列），不建立任何資料。
*   **AC-B2：圖文區塊已達上限**
    *   **Given**: 使用者位於新增頁面畫面，畫面已呈現 3 組圖文區塊。
    *   **When**: 使用者嘗試點擊「新增圖文區塊」。
    *   **Then**: 該按鈕應呈停用狀態且不可點擊，畫面維持 3 組區塊，不新增第 4 組亦不顯示錯誤提示。
*   **AC-B3：圖文區塊不可移除至零組**
    *   **Given**: 使用者位於新增頁面畫面，畫面僅呈現 1 組圖文區塊。
    *   **When**: 使用者嘗試移除該組區塊。
    *   **Then**: 該組之「移除」按鈕不得顯示，使用者無法將圖文區塊移除至 0 組。
