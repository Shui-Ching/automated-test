# [PAG-ADM-FN-003] 後台 編輯頁面

## 1. 商業邏輯

| 項目 | 定義 |
| :--- | :--- |
| **需求描述** | 身為 後台管理人員，我想要 修改既有頁面之圖文區塊與內容，以便於 隨時更新前台呈現的資訊。 |
| **使用對象** | 後台管理人員 |
| **前提條件** | 使用者已完成後台登入，且目標頁面資料存在於系統中。 |
| **基本流程** | 1. 使用者於頁面列表點擊某筆資料之「編輯」進入本畫面。<br>2. 系統依主鍵讀取該筆資料，帶入各欄位現值，並依原儲存順序還原全部圖文區塊。<br>3. 使用者修改欲異動之欄位。<br>4. 使用者點擊「新增圖文區塊」追加一組，或點擊任一組之「移除」刪除該組。<br>5. 使用者點擊「儲存」。<br>6. 系統驗證欄位規則後更新資料，反饋成功訊息並導回 `[PAG-ADM-FN-001] 後台 頁面列表`。 |
| **異常流程** | 1. 若頁面名稱與其他資料重複，阻擋儲存並提示對應錯誤訊息。<br>2. 若該筆資料於編輯期間已被刪除，阻擋儲存並提示「資料不存在或已被刪除」，導回頁面列表。 |
| **特殊規則** | 1. 頁面名稱唯一值檢核時排除本筆資料，維持原值儲存不視為重複。<br>2. 圖文區塊組數之上下限、順序規則與各組獨立性同 `[PAG-ADM-FN-002] 後台 新增頁面`。<br>3. 各組區塊圖片未重新上傳時沿用原圖片，點「垃圾桶」清除後該組必須重新上傳才可儲存。<br>4. 移除圖文區塊之異動於點擊「儲存」後方才生效，點擊「返回」則原資料不受影響。<br>5. 其餘欄位規則同 `[PAG-ADM-FN-002] 後台 新增頁面`。<br>6. 本頁之存取權限阻斷依 `NFR-001`；登入逾時處理依 `NFR-002`；資料寫入失敗處理依 `NFR-004`。 |
| **參考資料** | 無 |

### 按鈕與動作
*   **新增圖文區塊**：於現有圖文區塊下方追加一組空白區塊。已達 3 組時本按鈕停用（採輸入即擋，不觸發錯誤提示）。
*   **移除（各組圖文區塊）**：自畫面移除該組區塊，其後各組依序上移；異動於點擊「儲存」後方才寫入。僅剩 1 組時本按鈕不顯示。
*   **儲存**：完成檢核後更新資料，Toast 提示文案為「儲存成功」，顯示後導回 `[PAG-ADM-FN-001] 後台 頁面列表`。
*   **返回**：不儲存放棄本次修改，導向回 `[PAG-ADM-FN-001] 後台 頁面列表`。
*   **通用行為**：儲存處理期間按鈕停用，防重複送出。

## 3. 驗收條件

### 正常情境（預期成功）

*   **AC-P1：正確帶入既有資料與全部圖文區塊**
    *   **Given**: 系統中存在頁面「品牌故事」，其建立日期為 2026-03-01，並儲存有 2 組圖文區塊，版型依序為「左圖右文」、「右圖左文」。
    *   **When**: 使用者於頁面列表點擊該筆之「編輯」。
    *   **Then**: 系統應開啟編輯畫面，帶入頁面名稱、建立日期、頁面內容與補充說明之現有值，並依原順序還原 2 組圖文區塊及各組之版型、圖片縮圖與圖說文字。
*   **AC-P2：修改指定組別之版型**
    *   **Given**: 使用者位於「品牌故事」之編輯畫面，第 2 組區塊版型現值為「右圖左文」。
    *   **When**: 使用者將第 2 組之區塊版型改選為「左圖右文」並點擊「儲存」。
    *   **Then**: 系統應更新該組版型、顯示成功提示（文案見〈按鈕與動作〉）並導向至「頁面列表」；第 1 組之版型不得受影響。
*   **AC-P3：新增圖文區塊至三組**
    *   **Given**: 使用者位於「品牌故事」之編輯畫面，現有 2 組圖文區塊。
    *   **When**: 使用者點擊「新增圖文區塊」，於新增之第 3 組選擇版型並上傳圖片後點擊「儲存」。
    *   **Then**: 系統應保存三組區塊，列表該筆之「圖文區塊」欄顯示為「3 組」。
*   **AC-P4：移除圖文區塊後儲存**
    *   **Given**: 使用者位於「品牌故事」之編輯畫面，現有 3 組圖文區塊，圖說文字依序為「甲」、「乙」、「丙」。
    *   **When**: 使用者點擊第 2 組之「移除」後點擊「儲存」。
    *   **Then**: 系統應僅保存 2 組區塊，其圖說文字依序為「甲」、「丙」，列表該筆之「圖文區塊」欄顯示為「2 組」。
*   **AC-P5：維持原頁面名稱儲存**
    *   **Given**: 使用者位於「品牌故事」之編輯畫面，頁面名稱維持原值不變。
    *   **When**: 使用者僅修改補充說明後點擊「儲存」。
    *   **Then**: 系統不得因唯一值檢核而阻擋儲存，應正常更新資料並顯示成功提示（文案見〈按鈕與動作〉）。
*   **AC-P6：返回不套用區塊移除**
    *   **Given**: 使用者位於「品牌故事」之編輯畫面，現有 3 組圖文區塊，且已點擊第 2 組之「移除」。
    *   **When**: 使用者點擊「返回」。
    *   **Then**: 系統不得寫入任何異動，重新進入該筆編輯畫面時仍應還原原本之 3 組圖文區塊。

### 阻擋情境（預期擋下）

*   **AC-B1：欄位驗證（概括）**
    *   **Given**: 使用者位於編輯頁面畫面。
    *   **When**: 任一欄位（含任一組圖文區塊內之欄位）不符〈欄位驗證〉表所定義之規則，使用者點擊「儲存」。
    *   **Then**: 系統應阻擋儲存，並於對應欄位觸發該規則之錯誤提示（規則與文案見〈欄位驗證〉表，此處不重列），原資料不得被異動。
*   **AC-B2：圖文區塊已達上限**
    *   **Given**: 使用者位於編輯頁面畫面，畫面已呈現 3 組圖文區塊。
    *   **When**: 使用者嘗試點擊「新增圖文區塊」。
    *   **Then**: 該按鈕應呈停用狀態且不可點擊，畫面維持 3 組區塊，不新增第 4 組亦不顯示錯誤提示。

### 例外情境（系統異常）

> 本區為系統層行為，不納入 AC 編號池，不列入客戶驗收範圍。

*   **EX-1：編輯期間資料已被刪除**
    *   **Given**: 同一帳號於兩個瀏覽器分頁分別開啟頁面列表與「品牌故事」之編輯畫面。
    *   **When**: 於列表分頁完成刪除「品牌故事」後，於編輯分頁點擊「儲存」。
    *   **Then**: 系統不得重新建立該筆資料，應觸發對應之異常提示（文案見商業邏輯表異常流程 2）並導回頁面列表。
